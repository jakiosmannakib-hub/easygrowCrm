# §11. Database Schema — EasyGrowCrm

**Status:** Final.
**Database:** PostgreSQL 16+. All timestamps `timestamptz`. All date-only fields `date` (interpreted in Asia/Dhaka).
**Encodes:** PRD + Amendments A–**L** + §9 + §10. Where this schema and the original PRD's JS object shapes differ, **this schema wins** (the JS shapes were prototype client-state, per Amendment A).

---

## 11.0 Conventions

- **IDs:** `text` primary keys using prefixed IDs (`pt_…`, `l_…`) generated by the app — keeps parity with the prototype's `uid()` convention and makes IDs self-describing in logs. Better Auth manages its own `user`/`session` IDs.
- **Hours stored as `numeric(6,2)` decimal hours** (1.5 = 1h 30m). h+m formatting happens at the UI edge only (PRD §8 convention).
- **Soft delete:** business tables carry `deleted_at timestamptz` — the app filters `WHERE deleted_at IS NULL`. Exceptions: `audit_log` (append-only, never deleted), Better Auth tables (managed by the library).
- **`updated_at`** on all mutable tables, maintained by trigger, used for optimistic concurrency on `project_tasks` (two managers reviewing simultaneously → second write is rejected, not silently lost).
- Enums are Postgres `CREATE TYPE` — invalid states unrepresentable.

```sql
create type user_role       as enum ('super_admin','team_leader','project_manager','admin_hr','employee');
create type task_status     as enum ('planned','in_progress','blocked','submitted','revision_required','approved','completed','cancelled');
create type task_priority   as enum ('low','medium','high','urgent');
create type review_decision as enum ('approved','revision_requested');
create type work_type       as enum ('in_office','remote','client_site');
create type break_type      as enum ('lunch','prayer','personal','meeting','internet_issue','power_issue','emergency','other');
create type signout_type    as enum ('normal','early','auto_closed','half_day');
create type leave_type      as enum ('sick','casual','emergency','half_day','wfh','late_arrival','early_leave','overtime');
create type leave_status    as enum ('pending','approved','rejected');
create type half_selection  as enum ('first_half','second_half');
create type proof_type      as enum ('url','google_doc','google_sheet','screenshot','file','loom','staging_url','published_url','report','other');
create type daily_task_status as enum ('planned','in_progress','done','partially_done','pending','blocked');

```

Note on `task_status`: the employee sign-out option **"Done — send to review"** is a UI label only (Amendment I). It maps to `submitted`. The string "completed" never travels from any employee-facing surface.

## 11.1 Identity (Better Auth + extensions)

Better Auth's CLI generates `user`, `session`, `account`, `verification`. We extend `user` via `additionalFields` (§9.2); the resulting shape:

```sql
-- Managed by Better Auth; shown for reference. Do not hand-edit its core columns.
create table "user" (
  id             text primary key,
  name           text not null,
  email          text not null unique,
  email_verified boolean not null default false,
  image          text,
  created_at     timestamptz not null default now(),
  updated_at     timestamptz not null default now(),
  -- EasyGrowCrm additionalFields (input:false — settable only by admin endpoints):
  role           user_role not null default 'employee',
  title          text,
  department     text,
  active         boolean not null default true,
  join_date      date
);

-- session / account / verification: Better Auth defaults, unmodified.
-- Deactivation = UPDATE "user" SET active=false + DELETE FROM session WHERE user_id=$1 (§9.4).
```

```sql
create index user_active_role_idx on "user"(active, role);
```

The min-two-managers invariant (§9.7-5) is enforced in the database, not only the app:

```sql
-- Invariant §9.7-5: at least two active manager-level users at all times.
-- Fires on any UPDATE that deactivates or demotes; blocks the deadlock
-- where the no-self-review rule has no eligible reviewer left.
create function enforce_min_two_managers() returns trigger as $$
begin
  if (select count(*) from "user"
      where active and role in ('super_admin','team_leader','project_manager')
        and id <> new.id) +
     (case when new.active and new.role in ('super_admin','team_leader','project_manager')
           then 1 else 0 end) < 2 then
    raise exception 'operation would leave fewer than two active manager-level users';
  end if;
  return new;
end $$ language plpgsql;

create trigger user_min_managers before update of active, role
  on "user" for each row execute function enforce_min_two_managers();
```

> **Rule (§9.5-4):** `role` and `active` are read from this table on **every request**. Never from the session payload.

```sql
create table accounts (

create index accounts_client_idx on accounts(client_id) where deleted_at is null;

create table projects (
  id           text primary key,
  account_id   text not null references accounts(id),   -- Amendment M: replaces client_id
  name         text not null,
  type         text not null,                 -- 'Retainer' | 'One-off' | template category
  status       project_status not null default 'active',   -- NEW: lifecycle (review fix #12)
  start_date   date not null,
  deadline     date,
  template_id  text,                          -- provenance only; project holds its own task copies
  created_by   text not null references "user"(id),
  created_at   timestamptz not null default now(),
  updated_at   timestamptz not null default now(),
  deleted_at   timestamptz,
  constraint deadline_after_start check (deadline is null or deadline >= start_date)
);

create index projects_account_idx on projects(account_id) where deleted_at is null;
create index projects_status_idx on projects(status) where deleted_at is null;
```

- **Amendment M (PUL-414).** `accounts` sits between `clients` and `projects`; `projects.client_id` is gone, and a project's client is `accounts.client_id`. Archiving an account is a soft delete (`deleted_at`), blocked while it has live projects; archiving a client is blocked while it has live accounts. The migration backfills one account per existing client (same name) and re-points existing projects to it.

- **`current_month` is not stored.** It's derived: months elapsed since `start_date` in Asia/Dhaka (resolves review issue "who increments it" — nobody; it's computed).
- **Deleting a project** = soft delete; the app must block it while any task is `submitted` (pending review), and cascades soft-delete to its tasks.

```sql
  created_by       text not null references "user"(id),

  updated_at       timestamptz not null default now(),

create index pt_board_idx    on project_tasks(project_id, status)      where deleted_at is null;
create index pt_assignee_idx on project_tasks(assignee_id, due_date)   where deleted_at is null;

create index pt_depends_idx  on project_tasks(depends_on)              where depends_on is not null;
```

**Removed vs. prototype shape:** `recurring` (Amendment D), `billable` (dead column — client portal and billing were cut in PRD §7; **decision: dropped.** Flag if you want it back). `checklist`, `subtasks`, `comments`, `submission`, `reviewHistory` → normalized below.

**Application invariants (enforced in `authorize()`/service layer — documented here because the schema alone can't express them):**
- `assignee_id` must never reference a user with `role = 'super_admin'` (Amendment E). Also enforced by trigger below.
- `assignee_id`/reviewer dropdowns exclude `active = false` users.
- Circular `depends_on` chains rejected on write (walk the chain, ≤ same project).
- Dependency lock: a task whose `depends_on` target is not `approved`/`completed` cannot be `submitted`. The stored status is **not** mutated to `blocked` by the lock (PRD §3.2.5 — display-only).

```sql
-- Belt-and-braces for Amendment E:
create function forbid_super_admin_assignee() returns trigger as $$
begin
  if new.assignee_id is not null and
     (select role from "user" where id = new.assignee_id) = 'super_admin' then
    raise exception 'super_admin cannot be a task assignee';
  end if;
  return new;
end $$ language plpgsql;

create trigger pt_no_sa_assignee before insert or update of assignee_id
  on project_tasks for each row execute function forbid_super_admin_assignee();
```

### 11.3.2 Submissions & reviews (the QC trail)

Each submit-for-review creates a **submission row**; each manager decision creates a **review row** pointing at it. A revision loop = multiple submissions on one task. This replaces the prototype's `submission` object + `reviewHistory[]` array and makes the Manager QA scorecard an indexed aggregate instead of a JSONB scan.

```sql
create table task_submissions (
  id           text primary key,
  task_id      text not null references project_tasks(id),
  submitted_by text not null references "user"(id),
  summary      text not null,
  hours        numeric(6,2),
  issues       text,
  proof_type   proof_type,
  proof_value  text,
  reviewer_id  text references "user"(id),      -- routing hint (§9.7): not a lock
  created_at   timestamptz not null default now(),
  constraint reviewer_not_submitter check (reviewer_id is distinct from submitted_by)
);
create index sub_task_idx     on task_submissions(task_id, created_at desc);
create index sub_reviewer_idx on task_submissions(reviewer_id) ;

create table task_reviews (
  id            text primary key,
  submission_id text not null references task_submissions(id),
  task_id       text not null references project_tasks(id),   -- denormalized for scorecard speed
  reviewer_id   text not null references "user"(id),
  submitter_id  text not null references "user"(id),           -- copied from submission at write time
  decision      review_decision not null,
  note          text,                                          -- app: required when decision='revision_requested'
  rating        smallint check (rating between 1 and 5),
  meta_rating   smallint check (meta_rating between 1 and 5),  -- Manager QA layer
  meta_by       text references "user"(id),
  meta_at       timestamptz,
  created_at    timestamptz not null default now(),

  -- §9.7 hard invariants, in the database:
  constraint no_self_review      check (reviewer_id <> submitter_id),
  constraint no_self_meta_rating check (meta_by is null or meta_by <> reviewer_id),
  constraint meta_fields_together check ((meta_rating is null) = (meta_by is null))
);
create index rev_scorecard_idx on task_reviews(reviewer_id, created_at desc);  -- Manager QA scorecard
create index rev_task_idx      on task_reviews(task_id, created_at);
create unique index one_review_per_submission on task_reviews(submission_id);  -- concurrency: second simultaneous reviewer fails cleanly
```

## 11.4 Templates — the Amendment J hierarchy

> The template model is the strict hierarchy **Template → Month → Category → Task → Subtask** (Amendment J; §14.4, §16.7, PUL-501). Nothing outside this hierarchy stores template tasks, and there is no parallel flat cache — `tplAllTasks` is the only flattener, in code, never in the schema.

```sql
create table templates (
  id          text primary key,
  name        text not null,
  description text,
  category    text,                  -- template-level badge: 'SEO', 'Website Design', …
  roles       text[] not null default '{}',
  created_by  text not null references "user"(id),
  created_at  timestamptz not null default now(),
  updated_at  timestamptz not null default now(),
  deleted_at  timestamptz          -- soft delete; running projects unaffected (they hold copies)
);

create table template_months (
  id          text primary key,
  template_id text not null references templates(id) on delete cascade,
  num         int not null,                    -- Month 1, 2, … (display + project_tasks.month at clone)
  name        text not null,                   -- 'Month 1 — January 10'
  start_month smallint not null check (start_month between 0 and 11),   -- 0 = January
  start_day   smallint not null check (start_day between 1 and 31),     -- clamped per month by the app (§14.4.3)
  position    int not null,
  constraint uq_month_num unique (template_id, num)
);
create index tm_template_idx on template_months(template_id, position);

create table template_categories (
  id        text primary key,
  month_id  text not null references template_months(id) on delete cascade,
  name      text not null,                     -- 'On-page SEO', 'Reporting', … (color map at UI edge)
  position  int not null
);
create index tcat_month_idx on template_categories(month_id, position);

create table template_tasks (
  id              text primary key,
  category_id     text not null references template_categories(id) on delete cascade,
  position        int not null,
  title           text not null,               -- may contain {{ClientName}} (PRD §3.3.3)
  role_hint       text,
  priority        task_priority not null default 'medium',
  est_hours       numeric(6,2),
  due_rule        jsonb not null,              -- see below
  qc_required     boolean not null default true,
  proof_required  boolean not null default false,
  client_visible  boolean not null default false,
  sop_url         text,
  checklist       text[] not null default '{}',  -- copied into task_checklist_items at instantiation
  expected_output text,
  constraint due_rule_kind check (due_rule->>'kind' in ('day','before_deadline','after'))
);
create index tt_category_idx on template_tasks(category_id, position);

create table template_task_subtasks (
  id        text primary key,
  task_id   text not null references template_tasks(id) on delete cascade,
  title     text not null,                     -- no done flag: 'done' is a live-task concept
  position  int not null
);
create index tts_task_idx on template_task_subtasks(task_id, position);
```

**The FK chain is the hierarchy** — a subtask cannot exist without a task, a task without a category, a category without a month, a month without a template. `on delete cascade` down the whole chain: deleting a month removes its categories, tasks, and subtasks in one statement (the confirm dialog in §14.4.5 says so).

**`due_rule` allowed shapes (Amendment D — `weekly`/`monthly` kinds are REMOVED):**

```
{ "kind": "day", "n": N }                       -- Day N from month start
{ "kind": "before_deadline", "n": N }           -- N days before deadline (0 = on deadline)
{ "kind": "after", "ref": "<template_task_id>" } -- day after the referenced task's due date
```

`after.ref` is a **template_task id** (not a position — positions are per-category and don't identify a task globally); §14.4.4's dependency dropdown lists every other task in the template by id. App-validated at template save: the ref must belong to the same template, no self-ref, no cycles (walk the chain). Repeating work is expressed as explicit numbered rows ("Rank check — week 1/2/3/4" with `day` rules).

**Instantiation (Start Project, §14.3.8 / PUL-506):** the wizard walks the hierarchy via `tplAllTasks` and clones each template task into `project_tasks` with `category` = the category's `name`, `month` = the month's `num`, `{{ClientName}}` substituted in `title`, `checklist[]` expanded into `task_checklist_items`, and each `template_task_subtasks` row cloned into `task_subtasks` (`done = false`). The live project holds **copies** — later template edits never touch running projects.

> **As built (PUL-506):** titles also substitute `{{ProjectName}}` and `{{MonthName}}` (the
> calendar month of the task's month start). The project row gets `template_id` = the template
> (provenance, still no FK) and `type` = the template's `category`, or `'Retainer'` when it has
> none. Each live task keeps the template's `role_hint`. Full detail: the §13.3.2 as-built note.

## 11.5 Attendance (§10 model)

```sql
create table attendance (
  id             text primary key,
  employee_id    text not null references "user"(id),
  date           date not null,                    -- Asia/Dhaka working date
  work_type      work_type not null,
  sign_in_at     timestamptz not null,
  late           boolean not null default false,    -- sign_in_at local time > settings.grace_in (09:15 seed default, §10.1)
  sign_out_at    timestamptz,
  sign_out_type  signout_type,                      -- NULL while day is open
  early_reason   text,                              -- required by app when sign_out_type='early'
  half_selection half_selection,                    -- set when sign_out_type='half_day'
  break_minutes  int not null default 0,            -- running total (maintained in the same tx as breaks)
  net_minutes    int,                               -- finalized at sign-out/auto-close; capped at shift end for auto_closed
  auto_closed_at timestamptz,
  created_at     timestamptz not null default now(),
  updated_at     timestamptz not null default now(),

  constraint one_row_per_day unique (employee_id, date),          -- kills "sign in twice"
  constraint early_needs_reason check (sign_out_type <> 'early' or early_reason is not null),
  constraint signout_after_signin check (sign_out_at is null or sign_out_at > sign_in_at)
);
create index att_history_idx on attendance(employee_id, date desc);
create index att_open_idx    on attendance(sign_out_at) where sign_out_at is null;  -- the auto-close job's scan

create table attendance_breaks (
  id            text primary key,
  attendance_id text not null references attendance(id) on delete cascade,
  type          break_type not null,
  started_at    timestamptz not null,
  ended_at      timestamptz,                        -- NULL = break currently running
  minutes       int,                                -- filled on end, rounded to nearest minute
  constraint ended_after_start check (ended_at is null or ended_at > started_at)
);
create index brk_att_idx on attendance_breaks(attendance_id);
create unique index one_open_break on attendance_breaks(attendance_id) where ended_at is null;  -- one break at a time
```

**Server-authoritative timer:** net working time is always computed server-side as `(now() - sign_in_at) - breaks`, never trusted from the client. Sign-out permitted when net ≥ 7h (or ≥ 3.5h with an approved half-day for `date`). **Auto-close job** (server cron, every 5 min): close any row where `now() - sign_in_at ≥ 10h` → end open break, set `sign_out_type='auto_closed'`, cap `net_minutes` at shift end.

**The atomic sign-out (§10.5)** touches, in ONE transaction: `attendance` + open `attendance_breaks` + `daily_tasks` statuses + `project_tasks` statuses + `task_submissions` inserts + `eod_reports` insert + `audit_log` rows. Notifications/webhooks fire after commit via queue.

```sql
create table eod_reports (
  id            text primary key,
  employee_id   text not null references "user"(id),
  date          date not null,
  completed     int not null default 0,
  total         int not null default 0,
  planned_hours numeric(6,2),
  actual_hours  numeric(6,2),
  explanation   text,      -- app: required if any task not done (PRD §3.4.3 rule, kept)
  blockers      text,
  issues        text,
  tomorrow      text,
  remarks       text,
  -- Lightweight manager acknowledgment (owner decision — no approve/revise loop, no score):
  reviewed_at   timestamptz,
  reviewed_by   text references "user"(id),
  flagged       boolean not null default false,   -- manager marks "needs a conversation"
  manager_note  text,
  created_at    timestamptz not null default now(),
  constraint one_report_per_day unique (employee_id, date),
  constraint ack_complete check ((reviewed_at is null) = (reviewed_by is null)),
  constraint no_self_ack  check (reviewed_by is null or reviewed_by <> employee_id)
);
create index eod_idx           on eod_reports(employee_id, date desc);
create index eod_unreviewed_idx on eod_reports(reviewed_at) where reviewed_at is null;  -- manager's "to read" list
```

**No `score` column anywhere** (Amendment H). The prototype's full EOD approve/revise loop is **replaced by lightweight acknowledgment** (owner decision): a manager can mark a report reviewed, optionally flag it ("needs a conversation") and leave a note. The employee's report content itself is immutable after sign-out — the acknowledgment fields are the only writable part, manager-only, and no-self-ack is a DB constraint. Semantics: `reviewed` = read; `flagged` = read and needs follow-up. No revision-resubmission cycle exists; follow-up is a human conversation, not a workflow.

EOD content immutability (§13.5.7, PUL-605) is enforced in the database via column-level grants.

> **DECIDED (Phase 1) — this block needs rework before PUL-605.** There is no `easygrowcrm_app`
> role (see §11.8): the app connects as the owning user, so these column grants have nothing to
> bind to. Follow the audit-log precedent and enforce EOD immutability with a **trigger** that
> rejects an UPDATE touching any column other than `reviewed_at`, `reviewed_by`, `flagged`,
> `manager_note`. The *rule* below is unchanged; only its mechanism is.

```sql
-- EOD content is immutable; only the acknowledgment columns are ever updatable.
revoke update on eod_reports from easygrowcrm_app;
grant  update (reviewed_at, reviewed_by, flagged, manager_note)
  on eod_reports to easygrowcrm_app;
-- INSERT stays granted (sign-out writes the report); DELETE is never granted.
```

## 11.7 Leave (with half-days)

```sql
create table leave_requests (

  constraint end_after_start   check (end_date >= start_date),
  constraint half_day_is_one_day check (type <> 'half_day' or (start_date = end_date and half_selection is not null and days = 0.5)),
  constraint no_self_decision  check (decided_by is null or decided_by <> employee_id),   -- §9.7-3
  constraint decision_complete check ((status = 'pending') = (decided_by is null))
);
create index lv_emp_idx    on leave_requests(employee_id, start_date desc);
create index lv_pending_idx on leave_requests(status) where status = 'pending';

create table leave_quotas (          -- per-type annual quota; seeded: sick 12, casual 10, emergency 5
  type      leave_type primary key,
  annual    numeric(4,1)             -- NULL = unquoted (wfh, late_arrival, early_leave, overtime)
);

create table holidays (              -- RECOMMENDED addition (review fix #11): BD public holidays
  date  date primary key,
  name  text not null
);
-- days computation for quota: count only Sun–Thu, excluding holidays rows.
```

**App rules:** quota balance = `annual − Σ days of approved quoted leaves this year`; balances display halves (7.5). Half-day approval for a date sets that day's timer target to 3.5h net and break allowance to 30m (§10.7).

> superuser session, where a REVOKE binds only the roles it names — and it needs no second DB user
> to provision, rotate, or get wrong in an environment. `TRUNCATE` is a different event and is not
> blocked, which is what lets test fixtures reset (PUL-109); a test asserts the trigger still bites
> after a truncate. §17's PUL-102.0 and 102.2 are superseded accordingly.
